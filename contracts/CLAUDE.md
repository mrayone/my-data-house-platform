# CLAUDE.md — contracts/

## O que é esta pasta

A **fonte da verdade da extensibilidade**. Um arquivo YAML por entidade é o
**único artefato editado à mão** por tópico. Dele são gerados o schema Avro, o
DDL de landing, a config do connector e a entrada do tópico Kafka.

Leia [`../docs/adr/0003-extensibilidade-contract-first.md`](../docs/adr/0003-extensibilidade-contract-first.md)
antes de mexer aqui.

## Estrutura

```
contracts/
├── CLAUDE.md          <- este arquivo
├── schema.json        <- JSON Schema que valida todo descritor
└── domains/<contexto>/<entidade>.yaml
```

`<contexto>` e `<entidade>` no caminho **devem** ser iguais a
`metadata.context` e `metadata.entity`. `dhctl contract validate` falha se
divergirem.

## Regras

1. **Nunca edite arquivo gerado** para "corrigir" algo. Corrija o contrato e rode
   `make generate`. Arquivos gerados carregam header `GENERATED by dhctl`.
2. **`source.version_column` é obrigatória e precisa ser monotônica por chave.**
   É a autoridade de ordem do CDC ([ADR-0004](../docs/adr/0004-semantica-cdc-dedup-ordem-delete.md)).
   Sem isso, evento fora de ordem sobrescreve estado novo com estado velho.
3. **`landing.order_by` termina em `_cdc_seq`** (L0 guarda todas as versões).
   **`core.order_by` NÃO inclui `_cdc_seq`** (com ele, nada deduplica).
   Essa assimetria é intencional e é o erro mais comum ao criar contrato.
4. **`landing.ttl_days` ≥ 90** e, na prática, ≥ retenção do Kafka. Sem isso,
   reprocesso deixa de ser possível.
5. **Dinheiro é `decimal`**, nunca `float64`. Check `dq.money.no_float` falha.
6. **Tipo fora da tabela de mapeamento** de
   [`../docs/architecture/extensibility.md`](../docs/architecture/extensibility.md)
   não se improvisa: adicionar tipo é alterar `internal/codegen/` e a tabela, no
   mesmo commit.
7. **`nullable: true` gera `["null", T]` com `default: null`** automaticamente —
   requisito da compatibilidade `BACKWARD`
   ([ADR-0006](../docs/adr/0006-convencoes-avro-e-schema-registry.md)).
8. **`relations` não gera JOIN.** Declara que a relação existe, para alimentar o
   mapa de data-flow, a validação de referência e os checks `dq.rel.*`. Como
   correlacionar é decisão do cenário.
9. **`expose_as_dictionary` só para cadastro pequeno** (até ~10M linhas)
   consultado por chave. Monitorar `system.dictionaries.bytes_allocated`.
10. **A chave da relação é `join_on`, não `on`.** Em YAML 1.1 a chave `on` é
    interpretada como o booleano `true`, e o campo desaparece silenciosamente.
    Pela mesma razão, **valor de `doc:` que contenha vírgula dentro de um flow
    mapping `{ ... }` precisa estar entre aspas** — sem elas a vírgula é lida
    como separador de entradas. `dhctl contract validate` pega os dois casos.
11. **Mudança incompatível de schema não edita o contrato existente:** cria
    `sap.<ctx>.<entidade>.v<n+1>` e um contrato novo. `v<n>` é versão de
    **contrato**, não de schema.

## Fluxo de trabalho

```bash
$EDITOR contracts/domains/<ctx>/<entidade>.yaml
dhctl contract validate contracts/domains/<ctx>/<entidade>.yaml
make generate
git diff                    # revise o que foi gerado
make bootstrap
dhctl dq run --severity error
```

Procedimento completo: [`../docs/runbooks/add-new-topic.md`](../docs/runbooks/add-new-topic.md).

## Como importar do cenário real

No ambiente real o schema já existe no Schema Registry. Nesse caso:

```bash
dhctl contract import --from-subject sap.sales.delivery.v1-value \
  --context sales --entity delivery > contracts/domains/sales/delivery.yaml
```

O import gera o rascunho a partir do subject. **As decisões de plataforma —
`order_by`, `ttl_days`, `version_column`, `relations`, `expose_as_dictionary` —
são preenchidas por um humano**, porque não estão no schema do SAP.
